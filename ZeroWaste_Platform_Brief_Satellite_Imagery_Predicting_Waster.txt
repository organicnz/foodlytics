1. The Problem — First Principles
Food waste is not one problem. It is the intersection of six compounding failures across the supply chain:

Root Cause
Mechanism
Biological decay
Every harvested item has an entropy clock. Nothing stops it — only delays it.
Forecast error
Farmer, distributor, retailer, consumer all forecast in isolation. Every mismatch is physical waste.
Misaligned incentives
Running out costs more than throwing away. Rational actors produce irrational collective waste.
Externalized costs
Disposal cost borne by society, not the discarding party. No price signal to change behavior.
Aesthetic filtering
Cosmetically non-standard produce culled before market. No nutritional basis for the standard.
Cold chain gaps
Infrastructure failure in low-income markets. Food loses the decay race before reaching a buyer.

Scale: 1/3 of all food produced globally is lost or wasted — approximately 2.5 billion tonnes per year. Estimated value: $1 trillion USD. CO₂ equivalent: 8-10% of global greenhouse gas emissions.

2. How Food Waste Is Actually Measured
Understanding the data methodology is critical before building any analytics platform. Every major report uses the same foundational equation:

Mass Balance Formula: Food Available − Food Consumed = Food Lost/Wasted

Food Available = Production + Imports − Exports − Non-food use
Food Consumed = Household survey estimates
The Gap = Loss at each supply chain stage

2.1 Data Sources
FAO Food Balance Sheets: Annual production, trade, utilization data per country. Primary input for all major reports.
UNEP Food Waste Index: Consumer + retail stage. Aggregates 1,000+ country studies. Uses kg/capita/year as unit.
ReFED (US): USDA commodity flows + waste composition studies. Produces dollar-value estimates.
Satellite / Remote Sensing: NDVI-based crop yield modeling. Emerging method — FAO and WRI expanding this.

Key Uncertainty: Consumer surveys consistently undercount by 30–50% vs physical waste audits. The FAO 1/3 figure carries a wide confidence interval. The math is straightforward — uncertainty lives entirely in the loss rate coefficients.

7. AI Layer Architecture
7.1 Gemini 3.5 Flash — Reasoning Over Real Data
Gemini is not a knowledge store. It is a reasoning layer. The data lives in Supabase. Gemini receives context from Supabase and reasons over it.

RAG Flow: User query → Supabase pgvector semantic search over embedded FAO/UNEP docs → top-k chunks retrieved → injected into Gemini 3.5 Flash context → grounded answer returned. Gemini never invents a food waste statistic. If the number is not in Supabase, it says so.

7.2 Educational Chat Layer
Any user on the public main page can ask food waste questions. Gemini 3.5 Flash queries the Supabase vector store and returns answers grounded in the ingested dataset. Not a generic chatbot — a domain-specific reasoning interface.

What percentage of food is wasted at the retail stage in South Asia? → Gemini queries loss_rate_coefficients table, returns the actual coefficient with source citation.
Which intervention has the highest ROI for a $500k budget? → Gemini queries v_priority_queue view, ranks by reduction_potential / projected_cost.
Why is the East Africa cold chain intervention underperforming? → Gemini queries intervention_actuals + risks tables, returns structured diagnosis.

7.3 Supabase Edge Function — Gemini Middleware
All Gemini calls route through a Supabase Edge Function. This keeps the API key server-side, enables caching of frequent queries, enforces rate limits per user tier, and logs all AI interactions for audit.

9.2 Satellite Imagery — Farm-Stage Loss Detection
Satellites do not see food waste directly. They measure spectral proxies that correlate with crop stress, yield gaps, and unharvested area. This covers approximately 28% of the total waste problem (farm and harvest stage) but with a resolution and frequency no ground survey can match.

What satellites measure
Index / Signal
Sensor
Food Waste Inference
NDVI
Sentinel-2, Planet
Crop health and biomass. Anomalous drops before visible wilting = stress event = pre-harvest loss risk.
NDWI
Sentinel-2
Crop water stress. Drought stress is a primary driver of pre-harvest field loss.
NDRE (Red Edge)
Sentinel-2, Planet
Earlier disease and nitrogen deficiency detection than NDVI. Catches stress 1–2 weeks earlier.
LST (Land Surface Temperature)
MODIS, Landsat
Heat stress zones within a single field at 30m resolution. Maps intra-field loss heterogeneity.
SAR Backscatter
Sentinel-1 (radar)
Detects standing crop residue vs clean harvest. Estimates unharvested area. Penetrates cloud cover — critical for tropical regions.
Yield gap model
Derived from above
Difference between modelled expected yield (historical NDVI curve) and actual. The gap is a field-level loss proxy.

Satellite data sources
Sentinel-2 (ESA): Free. 10m resolution, 5-day revisit. The backbone of most academic food loss work. FAO and WRI both use Sentinel-2 NDVI in their loss coefficient models.
Planet Labs: Commercial. Daily 3m resolution of every agricultural field on earth. Used by agri-insurers for crop damage claims today.
NASA MODIS / VIIRS: Free. Coarser (250m–500m) but daily. Used for continental-scale yield anomaly detection and early warning.
Google Earth Engine: Processing layer. Makes all of the above queryable at scale without downloading petabytes. Callable from Python with a 20-line API call.

How satellite feeds into the platform
Coefficient updater: Sentinel-2 NDVI anomaly scores per region/commodity → Earth Engine API → Supabase Edge Function → updates loss_rate_coefficients table with source='satellite'. Gemini reasons over coefficients that are weeks old, not years old like the FAO annual survey.
Antigravity early warning: If satellite detects a large NDVI anomaly in a region with active interventions, PerformanceWatcher pre-emptively flags those interventions as at-risk — 2–4 weeks before intervention_actuals numbers come in.

Honest limitations of satellite data
Covers farm/harvest stage only — approximately 28% of total waste. Cannot see storage, transit, retail, or consumer losses.
Resolution floor: even at 3m you cannot identify individual damaged fruit. You identify stressed zones, not culled items.
Tropical cloud cover: Sentinel-2 (optical) blind during monsoon season in South/Southeast Asia and Sub-Saharan Africa. Sentinel-1 SAR compensates partially.
Ground truth required: NDVI anomaly → yield gap is a model inference. Requires periodic field survey calibration to remain accurate.

10. What AI Cannot Solve — Honest Gaps
The platform addresses information and coordination failures extremely well. It cannot address:

Problem
Why AI Cannot Fix It Alone
Policy and regulation
Incentive restructuring requires governments. The platform can surface the data that makes the case, but cannot enforce.
Cold chain capital
Physical refrigeration infrastructure requires development finance, not algorithms.
Consumer behavior change
Nudges help at the margin. Habits formed over decades are stubborn. Opt-out rates may exceed 40% for notification agents.
Global data standardization
FAO and national governments need to agree on schemas and reporting frequencies before the coefficients become reliable at country level.
Biological decay
Entropy cannot be stopped. Cold chain and packaging delay it. The platform optimizes the delay, not the decay.

Honest Assessment: The architecture for a global food waste intelligence platform was a $50M enterprise project two years ago. With Gemini 3.5 Flash, Gemma 4 (Apache 2.0), Supabase, and Next.js, it is buildable by a small team on GCP + Vercel in months. The technology barrier has collapsed. The data quality and policy barriers have not.

13. Gap-Closing Addition 1 — Gemini Omni Fridge Scan
The highest-impact addition for the Cerebral Valley hackathon. Directly uses Gemini Omni Flash, the flagship I/O 2026 generative media model. Closes the multimodal gap from 7/10 to 9/10.

13.1 What It Does
User photographs their fridge or a supermarket shelf. Gemini Omni Flash analyzes the image and returns:
A per-item inventory list with identified food categories
Estimated days to expiry per item based on visual freshness signals
Waste probability score (0–100) per item
Suggested actions: cook tonight, freeze, donate, or discard
Running household waste estimate aggregated over time

13.2 Why This Wins at the Hackathon
Gemini Omni Flash is the most visible I/O 2026 release. Showing it applied to a real consumer problem — reducing personal food waste — in a working demo is exactly what the DeepMind team wants to see. It also bridges the platform from B2B supply chain tool to consumer-facing product, dramatically expanding the addressable market story.

13.3 Buildable Code Spec
Android Implementation: // 1. Capture image via CameraX (already in ClaimReady stack)

14. Gap-Closing Addition 2 — Antigravity 2.0 Two-Agent Monitoring Loop
A minimal but genuine agentic implementation using Antigravity 2.0. Closes the agentic gap from 6/10 to 9/10. Scoped deliberately small so it is buildable and demoable in one day.

14.1 What It Does
Two agents run continuously on Google Cloud via Antigravity 2.0:

Agent
Name
Behaviour
Agent 1
PerformanceWatcher
Polls intervention_actuals table in Supabase every 15 minutes. Calculates actual_reduction_tonnes / projected_reduction_tonnes ratio. If ratio drops below 0.80 (80% of projected) for two consecutive periods, fires a trigger to Agent 2.
Agent 2
BriefGenerator
Receives trigger from Agent 1 containing the intervention_id and the underperformance delta. Queries Supabase for the intervention record, regional context, and the risks table. Calls Gemini 3.5 Flash to generate a structured corrective brief. Writes the brief to a briefs table and sends a push notification to the operator.

14.2 Why Two Agents, Not One
Separation of concerns. PerformanceWatcher is a deterministic polling agent — no AI needed, just arithmetic against Supabase. BriefGenerator is the AI reasoning layer. Keeping them separate means PerformanceWatcher can fire multiple downstream agents in future (slack alert, email, dashboard flag) without touching the AI logic. This is the Antigravity 2.0 multi-agent architecture in its simplest correct form.

14.3 Buildable Code Spec
Agent 1 — PerformanceWatcher (Antigravity 2.0 / Python): import antigravity as ag
import supabase

@ag.agent(schedule='*/15 * * * *')  # every 15 min
def performance_watcher():
    sb = supabase.create_client(SUPABASE_URL, SUPABASE_KEY)
    
    # Fetch latest two periods per intervention
    actuals = sb.table('intervention_actuals') \
        .select('intervention_id, actual_reduction_tonnes, projected_reduction_tonnes, period') \
        .order('period', desc=True).limit(100).execute()
    
    # Group by intervention, check last 2 periods
    for intervention_id, rows in group_by_intervention(actuals.data):
        last_two = rows[:2]
        if all(r['actual'] / r['projected'] < 0.80 for r in last_two):
            ag.trigger('brief_generator', payload={
                'intervention_id': intervention_id,
                'delta': last_two[0]['actual'] / last_two[0]['projected']
            })

Agent 2 — BriefGenerator (Antigravity 2.0 / Python): @ag.agent(trigger='brief_generator')
def brief_generator(payload):
    sb = supabase.create_client(SUPABASE_URL, SUPABASE_KEY)
    intervention_id = payload['intervention_id']
    delta = payload['delta']
    
    # Pull context from Supabase
    intervention = sb.table('interventions').select('*').eq('id', intervention_id).single().execute()
    risks = sb.table('risks').select('*').eq('intervention_id', intervention_id).execute()
    
    # Build Gemini prompt with real data
    prompt = f"""
    Intervention: {intervention.data['name']}
    Stage: {intervention.data['stage']}
    Region: {intervention.data['region']}
    Performance: {delta:.0%} of projected reduction delivered
    Active risks: {[r['description'] for r in risks.data]}
    
    Generate a structured corrective brief with:
    1. Root cause hypothesis (2-3 sentences)
    2. Three immediate actions ranked by impact
    3. Leading indicator to watch next 30 days
    """
    
    brief = call_gemini_35_flash(prompt)
    
    # Write to Supabase
    sb.table('briefs').insert({
        'intervention_id': intervention_id,
        'content': brief,
        'triggered_at': 'now()'
    }).execute()
    
    # Push notification to operator
    ag.notify(operator_id=intervention.data['operator_id'], message=f'Intervention underperforming at {delta:.0%} — brief generated')
